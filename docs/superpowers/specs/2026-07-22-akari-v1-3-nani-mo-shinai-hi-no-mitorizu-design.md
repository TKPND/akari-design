# あかり v1.3 画集『何もしない日の見取り図』設計書

**Version:** 1.0

**Date:** 2026-07-22

**Status:** Approved in conversation on 2026-07-22

## 1. 目的

『何もしない日の見取り図』は、Akari v1.3 Base Definitionを使った最初の
短編画集である。

小説とは異なる世界線のあかりが、コンパクトな1Kで一人きりの休日を
過ごす。大きな出来事、恋愛相手、画面外の同居人は置かない。姿勢、光、
家具、小物の移動だけで、朝から夜までの時間を描く。

本作の中心命題は次のとおり。

> 何も起きない一日は、上から見ると少しずつ形を変えている。

## 2. 既存成果物との差分

- v1.3 Base Definitionの6枚は設定と本人性を確定する資料であり、本作は
  その本人が生活している場面を見せる。
- v1.1 Situation Daybookは景色と生成ノートを含む横長の場面集だが、本作は
  A4縦、説明なし、室内のみの閲覧優先画集とする。
- v1.2画集『雨のせいにして』は恋人同士の完全POV物語だが、本作は
  小説と異なる世界線の一人きりの休日である。
- 本作は俯瞰構図を主役とし、真上7枚と斜め上5枚で構成する。

## 3. 成功条件

- 台詞や場面説明がなくても、一日の時間変化が12枚の順序から読める。
- 12枚すべてが同じv1.3のあかりに見える。
- 真上構図でも顔、エアリーボブ、健康的な脚、自然な身体接続が保たれる。
- 同じ1Kとして家具配置、縮尺、窓、ベッド、ラグ、キッチンが連続する。
- 光、小物、衣装の追加と髪飾りの着脱が時系列に矛盾しない。
- 俯瞰が身体強調や覗き見の印象にならず、非性的な日常表現を保つ。
- 18ページのA4縦PDFとして閲覧でき、時刻は検索可能なネイティブ文字に
  なる。
- v1.3 Base Definition、v1.2、legacyの既存成果物を変更しない。

## 4. 非目的

- 小説「壁一枚のとなり」の物語、関係性、たかひろの存在を描かない。
- 恋愛、デート、来客、外出、大きな事件を追加しない。
- 新しい基本衣装、髪型、体型、顔、年齢設定を定義しない。
- 12場面とは別に、表紙専用の第13場面を生成しない。
- 台詞、独白、場面名、説明文を本文ページへ載せない。
- 生成画像へ題名、時刻、ロゴ、透かし、ページ番号を焼き込まない。
- v1.3 Core設定PDFを本フェーズで作らない。

```text
    └── checksums.txt
```

`source/candidates/`と生成された比較画像はローカル作業物としてgit管理外に
置く。採用12枚、参照スナップショット、manifest、レビュー証拠、リリース
PDF、checksumを恒久成果物とする。

候補から採用先へは画像変換を挟まず、PNGをバイト同一で昇格する。昇格時に
`cmp`とSHA-256一致を記録する。

未追跡候補が存在する制作環境では、validatorが候補と採用先のバイト一致を
直接検証する。clean checkoutでは候補PNGを要求せず、review evidenceに保存
した候補SHA-256と採用PNGのSHA-256一致を永続証拠として検証する。

## 6. 本の形式

- 判型: A4縦、210 x 297 mm
- 本文画像: 4:5縦
- 本文画像の最低寸法: 1024 x 1280 px
- 色空間: sRGB
- 本文画像数: 12枚
- 総ページ数: 18ページ
- 本文文字: 各場面の時刻のみ
- 画像内文字: 禁止

ページ構成は次のとおり。

| ページ | 内容 |
| --- | --- |
| 1 | 表紙。最も強い承認済み真上構図を再トリミング |
| 2 | 部屋と小物のディテール。承認画像を再トリミング |
| 3 | 扉。題名のみ |
| 4-15 | Scene 01-12を1場面1ページで収録 |
| 16 | Scene 12の寝具と髪飾りを使った余韻 |
| 17 | 制作情報、v1.3表記、バージョン |
| 18 | 裏表紙、リリースID、checksum参照 |

表紙、2ページ目、16ページ目は承認済み12枚の安全な再トリミングだけを
使う。頭、手、足、髪飾り、重要な小物を切断するトリミングや、人物の
引き伸ばしは禁止する。

本文ページに場面名、説明、台詞、ページ番号は表示しない。時刻、題名、
制作情報はPDFレンダラーがネイティブ文字として描画する。

## 7. 部屋の固定設計

12場面の前に、人物なしの俯瞰ルームアンカーを1枚制作する。この画像は
本文に収録せず、空間、家具、色、縮尺の制作参照として恒久保存する。

固定配置は次のとおり。

- 画面上: 窓、淡いブルーのカーテン、小さな観葉植物
- 画面右: 低いベッド、白い寝具
- 中央: 生成りのラグ、丸みのあるローテーブル、床クッション
- 画面左: 小さなキッチン
- 画面下: 低い棚、部屋の出入口
- 基本色: 明るい木、オフホワイト、淡いブルー、少量の暖色

家具、窓、出入口は一日を通して動かさない。本、マグ、洗濯物、スマホ、
クッション、ブランケットだけが移動し、時間の経過を示す。

ルームアンカーは建築図面や天井を外したドールハウスではない。人物を置いた
時に生活空間として自然に見える、柔らかなアニメ背景の俯瞰イラストとする。

## 8. 光、衣装、髪飾りの連続性

### 8.1 光

| 時間帯 | 光 |
| --- | --- |
| 朝 | 窓から入る淡い斜光 |
| 昼 | 明るく均一な自然光 |
| 夕 | 床を横切る琥珀色の光 |
| 夜 | 青灰色の窓と柔らかな暖色の室内灯 |

### 8.2 衣装

全場面の基本衣装は、ゆるい白い半袖Tシャツと淡いブルーのルームショーツ
で固定する。

- Scene 01-08: 基本衣装、原則として素足
- Scene 09-11: 薄手カーディガンと室内ソックスを追加
- Scene 12: カーディガンとソックスを外し、基本衣装で寝具へ戻る

服の追加や除去で顔、体型、年齢印象を変えない。

### 8.3 髪飾り

- Scene 01: 外し、枕元に置く
- Scene 02-07: character-leftに正しく着用する
- Scene 08: 昼寝前に外し、ローテーブル上へ置く
- Scene 09-11: 再び正しく着用する
- Scene 12: 外し、枕元へ戻す

外している場面でも、淡いブルーの交差ピンと小リボンの一式を画面内へ
置く。欠落、重複、左右反転、別形状への変化を許可しない。

## 9. カメラ契約

- 真上構図: 75-90度、7枚
- 斜め上構図: 45-60度、5枚
- 極端な広角、魚眼、実在不可能な折れた床面を使わない。
- 人物が小さすぎる全室ドールハウス構図を使わない。
- 俯瞰でも顔、手、足、髪飾り、行為の中心が読める距離を保つ。
- 家具や画面端で頭、手、足を不自然に切らない。
- 胸、腰、脚を意図的に強調するカメラやポーズを使わない。

真上構図では短縮表現を魅力として使うが、首、肩、骨盤、膝、足首を切断・
省略してよい理由にはしない。

## 11. 参照画像の権限

各生成前に、使用する参照画像を実際に開き、役割を確認する。v1.3参照は
パッケージ内へバイト同一でコピーし、元パス、役割、SHA-256を
`manifest/references.yaml`へ記録する。

- V13-01: 顔、琥珀色の瞳、エアリーボブ、着用時の髪飾り
- V13-02: 全身体型、健康的な脚、重心、関節接続
- V13-03A: 日常の力が抜けた表情
- V13-04B: 白T、淡青ショートパンツ、全身での部屋着
- ルームアンカー: 家具、色、縮尺、空間方向

直前の承認場面は、小物位置、光、部屋の連続性だけを補助できる。顔、髪、
体型、描画の本人性を直前場面から連鎖継承しない。毎回v1.3 Base参照へ
戻すことで世代ごとのidentity driftを防ぐ。

## 12. 制作フロー

```text
approved design
  -> package and validation contracts
  -> immutable v1.3 reference snapshots
  -> room anchor candidates A/B
  -> accepted room anchor
  -> Scene 06 overhead pilot candidates A/B
  -> accepted overhead visual grammar
  -> remaining scenes in Act order
  -> Act contact sheets and continuity reviews
  -> full 12-scene continuity sheet
  -> 18-page portrait PDF
  -> raster and release audit
```

### 12.1 生成単位

- 1リクエストは1場面、1構図、1枚だけを対象とする。
- コラージュ、グリッド、複数時刻、複数衣装を禁止する。
- ルームアンカーと各場面は、初回に独立したA/Bの2候補を生成する。
- エージェントがhard gateを先に判定し、Pass候補だけをユーザーへ提示する。
- ユーザーが選択するまで採用先へ昇格しない。
- ユーザーが選択した候補だけをバイト同一で昇格する。

### 12.2 制作順

1. ルームアンカーを承認する。
2. Scene 06を俯瞰パイロットとして承認する。
3. Scene 01-03を制作し、朝のcontact sheetを確認する。
4. Scene 04-05を制作し、Scene 06と合わせて昼を確認する。
5. Scene 07-09を制作し、午後から夕方を確認する。
6. Scene 10-12を制作し、夜を確認する。
7. 12枚の時系列contact sheetを確認する。
8. 表紙に使う最も強い真上構図を選び、PDFを作る。

## 13. レビュー順序

候補は必ず次の順序でレビューする。

1. **Identity:** 同じv1.3のあかりか、若い成人として読めるか。
2. **Hair:** エアリーボブと髪飾りの着脱状態が正しいか。
3. **Camera:** 指定した俯瞰角度で、行為と構図が読めるか。
4. **Body:** 首、肩、骨盤、手足、短縮、接地が自然か。
5. **Room:** 家具配置、縮尺、窓、ベッド、ラグ、キッチンが連続するか。
6. **Continuity:** 光、衣装、小物、髪飾りが時系列に合うか。
7. **Rendering:** v1.3の線、色、光、仕上げが保たれるか。
8. **Production:** 4:5、最低寸法、sRGB、文字・ロゴ・透かしなしを満たすか。

次はMajorとして不採用にする。

- 別人化、子ども化、顔や体型の大幅な漂流
- 髪飾りの左右反転、欠落、重複、着脱時の不自然な消失
- 首、肩、骨盤、手足、指、短縮表現の破綻
- 家具の大幅移動、部屋の左右反転、不整合な縮尺
- 人物が小さすぎるドールハウス構図
- 胸、腰、脚を意図的に強調する性的または覗き見的な構図
- 読める文字、ロゴ、透かし、複数場面、コラージュ

最終候補がhard gateをすべて通る場合、表情の読み、人物の魅力、構図の
完成度、画集としての余韻が最も強い画像を優先する。

## 14. 再試行と失敗時の扱い

- 再生成では、一度に変更する主因を一つに限定する。
- 同じMajorが2ラウンド続く場合は、ポーズまたはカメラ角度を簡略化する。
- 真上で顔や関節が崩れる場合は、真上枚数を維持するため別の場面と角度を
  入れ替えてよい。ただし全体で真上7枚、斜め上5枚を守る。
- 部屋の連続性だけが崩れた場合も、identity参照を外さない。
- 前後場面と矛盾した場合は、原則として後から制作した場面を修正する。
- Majorを「後で直す前提」で採用しない。
- 低差分合成が髪、手足、衣服、家具を切断する場合は、差分量より視覚的
  連続性を優先する。

## 15. 検証設計

### 15.1 日常編集ゲート

`gate:edit:v1-3:nani-mo-shinai-hi-no-mitorizu`

- manifest schema
- 参照パスとSHA-256
- 候補、review、acceptedのlifecycle
- PNG、4:5、最低寸法、sRGB
- 髪飾り、文字、ロゴ、透かしのレビュー記録

Chromium、PDF build、全ページraster、OCRは実行しない。

### 15.2 時間帯統合ゲート

`gate:integration:v1-3:nani-mo-shinai-hi-no-mitorizu`

- 各Actのaccepted画像数
- 家具、衣装、髪飾り、光、小物の連続性
- Act contact sheetとレビュー完了
- 12場面完成時のfull continuity review
- `gate:integration:v1-3`によるBase Definition回帰

### 15.3 リリースゲート

`gate:release:v1-3:nani-mo-shinai-hi-no-mitorizu`

- A4縦、18ページ
- 12枚の本文画像と正しい時刻順
- qpdf構造検証
- 埋め込みUnicodeフォント
- 検索可能な題名、時刻、制作情報
- 全ページrasterと非空白検証
- checksum一致
- 最終視覚レビュー記録

PDF build、Chromium、Poppler、OCRを含む重い処理はリリースゲートで直列に
実行する。
