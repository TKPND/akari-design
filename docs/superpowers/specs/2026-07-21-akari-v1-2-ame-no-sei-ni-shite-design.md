# あかり v1.2 画集『雨のせいにして』設計書

**Version:** 1.0

**Date:** 2026-07-21

**Status:** Approved by user on 2026-07-21

## 1. 目的

『雨のせいにして』は、恋人になった後のあかりとたかひろが、雨で予定を変更した一日を過ごす完全 POV の短編画集である。

読者の視点をたかひろに固定し、朝の誘い、突然の雨、予定のない午後、隣室へ戻る直前の別れ惜しさまでを 12 枚の連続したイラストで描く。

本作の中心命題は次のとおり。

> 予定が消えたことで、二人の時間だけが残る。

## 2. 既存画集との差分

既存成果物は、設定、表情、衣装、仕草、屋内外のシチュエーション、朝から夜の日常場面を広く扱っている。本作は新しい場面を並べる画集ではなく、次の三点で明確に差別化する。

- 12 枚が同じ一日の時系列として連続する。
- 全場面をたかひろの一人称視点へ固定する。
- 天候、衣装、濡れ方、光、距離の変化を物語の一部として管理する。

単独で成立する美麗イラストの集合より、ページを順番にめくった時の感情の変化を優先する。

## 3. 成功条件

本作は次の条件をすべて満たした時に成功とする。

- 台詞を隠しても、朝から夜へ進む一日と二人の距離の変化が読める。
- 全場面が同じ 25 歳のあかりに見える。
- 屋外衣装、室内衣装、髪、髪飾り、体型が場面間で連続している。
- 雨量、髪と服の濡れ方、室内での乾き方が時間順に矛盾しない。
- カメラが全場面でたかひろの実在可能な位置にある。
- 最終場面まで、たかひろの姿を描かなくても二人でいることが伝わる。
- 最後のページに、隣室へ戻るだけでも別れたくない甘さが残る。
- v1.2 Core の identity、体型、色、既存 accepted 画像のバイト列を変更しない。

## 4. 非目的

- たかひろの顔、髪型、体型、衣装を新規設定すること。
- 二人の関係成立までを説明すること。
- 大きな事件、喧嘩、告白、旅行、記念日を扱うこと。
- 複数の日、季節、世界線を横断すること。
- 新しいあかりの基本衣装や髪型を設定すること。
- Core または Daily の accepted アセットを差し替えること。
- 生成画像へ台詞、題名、ロゴ、ページ番号を直接描画すること。

## 5. 成果物とパッケージ境界

本作は Core、Daily、既存画集から独立した v1.2 画集パッケージとする。

```text

├── manifest/
│   ├── book.yaml
│   ├── continuity.yaml

```

このパッケージの PDF は設定資料 PDF を置き換えない。リポジトリのデフォルト設定 PDF は引き続き `akari-v1.2/release/akari-v1.2-core-settings.pdf` とする。

`source/candidates/` と生成された contact sheet は作業中の生成物として git 管理外に置く。manifest、採用画像、review evidence、release PDF を保存対象とする場合も、実装完了後にユーザーが明示的に承認した範囲だけをコミットする。

## 6. 本の形式

- 用紙: A4 横
- 本文画像: 3:2 横長
- 本文画像の最低寸法: 1536 x 1024 px
- 本文画像数: 12 枚
- 総ページ数: 18 ページ
- 台詞: 1 場面につき 0 行または 1 行
- 画像内文字: 禁止

ページ構成は次のとおり。

| ページ | 内容 |
| --- | --- |
| 1 | 表紙。Scene 06 の承認画像を基にしたトリミングを使い、新しい第 13 の場面は生成しない |
| 2 | 雨粒と街のディテール。Scene 03 の承認画像から派生 |
| 3 | 扉、題名、短い導入文 |
| 4-15 | Scene 01-12 を 1 場面 1 ページで収録 |
| 16 | Scene 12 後の余韻。承認画像の静かな部分を再トリミングし、新規場面は追加しない |
| 17 | 制作ノート、クレジット、バージョン情報 |
| 18 | 裏表紙、リリース識別子、チェックサム参照 |

3:2 の画像は A4 横ページに無理な全面トリミングをせず、上下の余白または台詞領域を使って収める。

## 7. 完全 POV 契約

### 7.1 基本ルール

- カメラは常にたかひろの目と身体が実在できる位置へ置く。
- カメラ高、あかりとの距離、視線の高さを場面の行動と一致させる。
- あかりは必要な場面でカメラの向こうにいるたかひろを見る。
- 手招き、身体の向き、待つ姿勢、差し出す物で画面外の相手を示す。
- 鏡、窓、金属、濡れた路面にも、たかひろの顔、全身、影を映さない。
- 第三者が二人を眺めるような俯瞰、背後、遠景カメラを使わない。

### 7.2 唯一の例外

Scene 12 では、あかりがつかむたかひろの袖の端だけを画面下端に含めてよい。手、腕、顔、反射は描かない。

この例外は、最後の接触を視覚的に強めるためのものであり、他の場面へ展開しない。

## 11. 感情とフレーミングの流れ

感情の流れは次の順序を守る。

1. 外へ向かう期待
2. 予定が壊れたことを共有する笑い
3. 雨が作る物理的な近さ
4. 何もしなくても成立する安心
5. 一日を終わらせたくない素直さ

フレーミングは Act 1 の全身から膝上、Act 2 の動きのある中景と近景、Act 3 の落ち着いた近景、Act 4 の夕景と別れの距離へ移る。

Scene 10 が物理的な最接近、Scene 12 が感情的な最接近となる。Scene 12 は顔だけを大きくせず、扉、廊下、袖を含むことで「帰る距離」と「引き止める動作」を同時に見せる。

## 12. 参照画像の構成

各生成前に、使用する参照画像を実際に開き、役割を確認する。

### 12.1 共通 Core 参照

- 顔と髪: C05 および C06 の最適な正面寄り参照
- 全身体型: C01
- 45 度の顔、髪飾り側: C03 hairpin-side
- 座位と自然な脚: C04
- 室内足元: C07 standing および seated

### 12.2 Act 固定ルック

- Scene 01 を承認した後、屋外衣装と乾いた髪の固定ルック参照とする。
- Scene 08 を承認した後、室内衣装とタオルドライ後の髪の固定ルック参照とする。
- Scene 01 または Scene 08 を単独の identity 参照として使わず、必ず Core 参照と併用する。
- Scene N の画像を Scene N+1 へ順番に連鎖させない。

この方式により、連続性を保ちながら世代ごとの identity 漂流を防ぐ。

## 13. 制作フローとデータフロー

```text
approved design
  -> book and continuity manifests
  -> Scene 01 outdoor look anchor
  -> Scene 08 indoor look anchor
  -> remaining scene requests by Act
  -> candidate review
  -> accepted scene images
  -> Act contact sheets
  -> full 12-scene continuity sheet
  -> 18-page PDF
  -> raster and release audit
```

### 13.1 生成単位

- 1 リクエストは 1 場面、1 構図、1 枚だけを対象とする。
- コラージュ、グリッド、分割画面、複数時刻、複数衣装を禁止する。
- 初回は各場面 2 候補を生成する。
- Scene 01 と Scene 08 を先に承認し、その後は Act 内の順番で進める。
- 一つの場面を承認するまで、次の場面を最終承認しない。

### 13.2 候補から PDF まで

1. 生成リクエストと参照画像の役割を manifest へ記録する。
2. 候補画像を `source/candidates/` へ保存する。
3. review evidence に採否、問題、選定理由を記録する。
4. 採用画像だけを `accepted/` へ昇格する。
5. Act 完了時に比較シートで衣装、濡れ方、光を確認する。
6. 12 場面完了時に時系列比較シートを作る。
7. 承認画像から 18 ページの PDF と checksum を生成する。

## 14. レビュー順序

候補は必ず次の順序でレビューする。

1. Identity: 同じあかりか、25 歳の成人女性に見えるか。
2. Hair: ボブ形状と character-left の髪飾りが正しいか。
3. POV: カメラ位置、視線、画面外のたかひろが成立するか。
4. Continuity: 衣装、濡れ方、時刻、光、持ち物が前後と一致するか。
5. Body: 手、脚、関節、接地、重心、動作が自然か。
6. Emotion: 場面の感情が大げさすぎず、台詞なしでも読めるか。
7. Rendering: soft anime、色、背景、雨、光が人物を埋もれさせていないか。
8. Production: 3:2、単一場面、文字なし、ロゴなし、透かしなしを満たすか。

## 15. Blocker 条件

次のいずれかがあれば候補を採用しない。

- 別人、幼い年齢感、顔や体型の大幅な漂流
- 髪飾りの左右反転、欠落、重複
- 細すぎる脚、長すぎる頭身、モデル立ちへの変化
- たかひろの顔、身体、手、反射、影の出現。ただし Scene 12 の袖端を除く
- 実在不可能なカメラ位置、第三者視点、過剰な俯瞰や煽り
- 雨が降る前の濡れ、帰宅後の濡れ増加、室内衣装の濡れ
- 衣装、バッグ、傘、マグの不自然な消失または増殖
- 手足、指、関節、接地の破綻
- 性的なカメラ、衣装、表情、身体強調
- 読める文字、ロゴ、透かし、コラージュ、複数場面

## 16. 再試行と失敗時の扱い

- 再生成では、一度に変更する主因を一つに限定する。
- identity を守るために、Core 参照を外したり弱めたりしない。
- 1 ラウンドは 2 候補とし、2 ラウンド連続で Blocker が残った場合は構図または動作を簡略化する。
- 2 ラウンド失敗後も同じ複雑な構図を反復しない。
- 前後場面と矛盾した場合は、原則として後から制作した場面を修正する。
- 先行場面自体に Blocker がある場合のみ、先行場面を再生成する。
- 不採用候補を削除せず、不採用理由と改善軸を evidence に残す。
- 低差分合成で手、袖、髪、傘、足元が切断される場合は、差分量より視覚的連続性を優先する。

## 17. 検証設計

実装時に次の named gate を追加する。

### 17.1 日常編集ゲート

`gate:edit:ame-no-sei-ni-shite`

- 変更対象 scene manifest の schema
- 参照パスと SHA-256
- 候補、review、accepted のリンク整合
- 画像形式、3:2、最低解像度
- 文字列、ロゴ、透かしのレビュー記録
- Scene 単位の lifecycle

このゲートでは Chromium、全 PDF raster、OCR を毎回実行しない。

### 17.2 Act 統合ゲート

- Act 内の accepted 画像数
- 屋外または室内衣装の一致
- 髪飾り側と体型の一致
- 濡れ方と光の順序
- Act contact sheet の生成と review 完了
- v1.2 Core accepted bytes の不変

共有 v1.2 コードや manifest 基盤を変更した場合は、既存の `gate:integration:v1-2` も実行する。

### 17.3 最終リリースゲート

`gate:release:ame-no-sei-ni-shite`

- Scene 01-12 に accepted が各 1 枚存在する
- 未解決の Blocker または Major がない
- 全 12 場面の continuity contact sheet が承認済み
- PDF が 18 ページである
- 全ページの raster、視覚確認、テキスト抽出が完了する
- 画像の欠落、意図しないトリミング、台詞の重なりがない
- release PDF と checksums.txt の SHA-256 が一致する
- デフォルト設定 PDF と v1.2 Core accepted bytes が不変である

## 18. 完了条件

本作は次の状態で完了とする。

- 12 場面すべてに採用画像と review evidence がある。
- Scene 01 と Scene 08 の固定ルック基準が記録されている。
- Act 1-4 と全体の continuity review が完了している。
- 18 ページのリリース PDF と checksum が生成されている。
- 専用 release gate と必要な v1.2 integration gate が成功している。
- Core と Daily の release 境界を変更していない。
- 画集を順番に見た時、台詞なしでも物語と感情の流れが読める。

## 19. 実装前の境界

本設計書は画集の内容、制作単位、レビュー、検証、リリース境界を定義する。画像生成、manifest 作成、スクリプト追加、PDF 実装は、ユーザーが本仕様書を承認した後に別の implementation plan で扱う。
