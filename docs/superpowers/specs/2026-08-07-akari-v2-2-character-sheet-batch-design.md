# Akari v2.2 Character-Sheet Batch Design

Status: approved by the user; ready for implementation planning.

Date: 2026-08-07.

## Goal

Generate twelve independent landscape character-sheet candidates for Akari
v2.2. Every candidate is one complete image generated by Imagegen and contains
four coordinated depictions of the same Akari. The batch exists for visual
selection; it does not promote or replace a canonical asset.

The twelve calls use the same reference roles and the same master prompt. This
keeps identity requirements constant while allowing Imagegen to vary the
layout, scale, spacing, and visual hierarchy naturally.

## Sheet Content

Each landscape sheet contains four independent but clearly matching depictions:

1. a face-scale, near-front view with a calm or softly friendly expression;
2. a face-scale three-quarter view with the warm open smile of the primary
   anchor;
3. a natural front-oriented full-body standing view;
4. a relaxed three-quarter full-body view with light, believable movement.

All four depictions must read as the same twenty-five-year-old woman, in the
same outfit and with the same facial and hair design. Imagegen may choose the
placement, relative scale, whitespace, overlap, and visual flow. The prompt
must not impose a mechanical grid, programmatic collage, panel template, or
fixed left-to-right arrangement.

Use a clean white to softly warm off-white reference-sheet background. Do not
render titles, labels, captions, measurements, logos, watermarks, borders, or
decorative pseudo-text.

## Identity Contract

Preserve these primary-anchor traits across every depiction:

- warm brown eyes with the same iris size, pupil position, eye spacing,
  upper-lid weight, catchlight pattern, gaze coordination, and mature-cute age
  impression;
- no crossed gaze, mismatched iris sizes, duplicate pupils, doubled irises,
  fused lashes, wandering highlights, or oversized doll-like eyes;
- chestnut asymmetrical bob with the longer mass gathered into one low side
  ponytail on character-left, a blue tie, soft flyaways, and the same warm
  highlight treatment;
- exactly one straight, slender, filled blue capsule hairpin above the
  character-left temple, visible on canvas-right in frontal views;
- the same softly rounded face, brows, small nose, blush treatment, open smile,
  and polished anime illustration finish as the primary anchor;
- loose plain white T-shirt, dark navy utility shorts with one pocket, white
  socks, and blue-and-white sneakers wherever the full outfit is visible.

The four figures must have plausible hands, feet, limbs, joints, necks, and
body proportions. Depictions may overlap as part of the generated layout, but
they must not merge anatomy, share limbs, crop through essential features, or
create extra body parts.

## Batch Strategy

Use the built-in Imagegen path. Run twelve separate generation calls rather
than a scripted compositor or deterministic layout program. Each call uses the
same two references in the same order and the same exact master prompt. Do not
use an output from one call as a reference for another call; the twelve
candidates remain independent samples from one fixed contract.

Save all candidates, the master prompt, source copies, returned generation
metadata, dimensions, hashes, and review notes under the ignored directory:

```text
tmp/akari-v2.2-character-sheet/r01/
```

Use stable candidate names `candidate-01.png` through `candidate-12.png`.
Do not overwrite existing files, stage generated material, create a mechanical
contact sheet, promote a candidate, or start a correction round during this
batch.

## Human Selection Boundary

The user will judge the images directly. Do not assign automated or agent
PASS/FAIL labels, score the candidates, rank them, or choose a winner. Preserve
and present the twelve authorized calls as generated so the user can compare
the eyes, identity, anatomy, hairpin, outfit, landscape readability, and
overall appeal visually. Do not silently replace a weak candidate with a
thirteenth call.

## Verification

Before generation:

- verify both reference hashes and dimensions;
- copy both references byte-for-byte into the ignored run directory;
- open both references at original detail and state their distinct roles;
- persist the exact master prompt before the first call;
- confirm all twelve output names are absent.

After each generation:

- copy the generated PNG into its assigned candidate path without overwrite;
- verify the PNG signature, dimensions, SHA-256, and byte identity against the
  built-in generated source when that source path is available;
- record the generation identifier or request identifier returned by the tool;
- open the saved output for presentation without assigning a quality verdict.

After the batch, confirm the bounded Git scope and that no canonical or tracked
image changed.

## Non-Goals

This batch does not run an automated visual audit, score or rank candidates,
choose or promote a winner, repair individual candidates, create a turnaround,
create a release package, update a manifest, build a PDF, add written character
lore, or redesign Akari beyond the supplied v2.2 draft.
