# Akari V2.2 段階編集探索デザイン

## 目的

全身化で本人性が崩れた新規場面生成ルートは再開せず、本人性と衣装が承認済みの Candidate 2 を編集対象として、近距離から中距離の範囲で当たり候補を探す。

## 入力と禁止事項

- Image A: Candidate 2。ユーザー承認済みの編集対象であり、衣装と現在の構図を保持する基準。
- Image B: Akari V2.2 正典ポートレート。唯一の顔本人性 authority。
- 正典フルボディは今回の3候補には使わない。
- 本人性不合格の Candidate 3 と過去の不合格画像は、入力、編集対象、crop、合成元、文章化した連続性情報のいずれにも使わない。
- 各候補は Candidate 2 から独立して生成し、候補同士を連鎖させない。

## 第1ラウンド

| 候補 | 変更する1要素 | 保持する要素 |
| --- | --- | --- |
| A | 画角を膝上から腰上寄りへ近づける | 顔、表情、衣装、姿勢、背景、光 |
| B | 開口笑顔を自然な閉じ口の微笑みへ変える | 顔形、衣装、画角、姿勢、背景、光 |
| C | 中立光を柔らかな朝の斜光へ変える | 顔、表情、衣装、画角、姿勢、背景 |

各候補は built-in `image_gen.imagegen` の別コールで生成する。参照は Image A と Image B の2枚だけにする。

## 判定フロー

1. 生成前に Candidate 2、正典ポートレート、正典フルボディを開く。正典フルボディは目視確認だけで入力には使わない。
2. 3候補を独立生成し、ローカルの `tmp/` 配下へ非破壊保存する。
3. 各候補について、正典ポートレート、直近の承認済み本人性対照、候補顔、候補全体を並べた比較artifactを作る。
4. 背景や衣装の出来とは分け、最初に本人性だけをユーザーへ確認する。
5. 不合格または保留の候補は後続入力に使わない。合格候補も、追加承認なしに正典やセット内アンカーへ昇格させない。

## 停止条件

- 編集対象または正典を開けない場合は生成しない。
- Candidate 2から外れた大きな構図変更、全身化、別ポーズ化が起きた候補は採用せず、同じ候補を再試行しない。
- 顔が小さすぎて比較不能、または明白な本人性不合格の場合は、その候補を除外する。
- 第1ラウンドの3候補以外は、ユーザーの判定を得るまで生成しない。

## 保存範囲

- 候補、crop、比較artifact、run記録は `tmp/akari-v22-stage-edit-exploration-2026-08-13/` に置く。
- 画像はGit追跡しない。
- 正式な受け入れ先への保存やmanifest更新は、ユーザーの明示承認後だけ行う。
